# 14. Шпаргалка терминов для совещания

> Для Димы: выживание при живых вопросах. Формат: термин → ответ одной фразой, как сказал бы специалист. Учить не надо — надо прочитать 3 раза.

## Хранилища

- **SAN vs NAS** — SAN отдаёт блочное устройство (диск) по сети (FC/iSCSI) — под виртуализацию и БД. NAS отдаёт файлы (NFS/SMB) — под документы и помойку. У нас: Ceph даёт блочное (RBD) виртуалкам, Nextcloud/Samba — файлы людям. Отдельного SAN нет — не нужен на 100 ВМ.
- **Ленточная библиотека (LTO)** — холодный архив на картриджах. LTO-9 = 18 ТБ, живёт 15–30 лет, WORM (нестираемый). Стандарт для налогового архива 5–10 лет: дёшево на ТБ, оффлайн (не зашифруют вирусом), картридж в сейф. «На прошлой фирме была» — потому что это и правда стандарт для бухгалтерии.
- **Бэкап vs архив** — бэкап: быстро восстановить вчерашнее (PBS на дисках). Архив: показать документ через 9 лет (лента). Это разные системы, обе есть в плане.
- **HCI** — гиперконвергенция: диски стоят прямо в серверах виртуализации, хранилище программное (Ceph). Не нужна отдельная СХД.
- **Ceph** — распределённое хранилище: данные размазаны по нодам с репликацией ×3, отказ сервера не событие. Встроен в Proxmox.
- **NVMe / SATA / NL-SAS** — NVMe: сверхбыстрые диски для виртуалок. NL-SAS: дешёвые большие — для бэкапов.
- **RAID vs репликация Ceph** — RAID защищает от отказа диска внутри сервера, репликация — от отказа сервера целиком. У нас второе.

## Виртуализация

- **KVM** — гипервизор в ядре Linux, основа Proxmox (и zVirt, и OpenStack). «Придумал KVM» = выбрал семейство технологий, на котором строится вся виртуализация бесплатно.
- **Гипервизор** — ОС, которая запускает виртуалки (Proxmox/ESXi).
- **HA-кластер** — виртуалка автоматически поднимается на другой ноде при отказе первой.
- **Live migration** — переезд работающей виртуалки между нодами без выключения.
- **Quorum** — большинство нод кластера, нужно чтобы кластер не раздвоился. Поэтому нод 4 (чётно), но Ceph mon — 3 (нечётно).
- **Блейды** — лезвия: много серверов-модулей в одном шасси. Нам не нужны (бизнес сам сказал): дорого, оверкилл на 12 нод, вендор-лок.

## Сеть

- **VLAN** — виртуальные изолированные сети поверх одной физики. У нас 10: пользователи, голос, Wi-Fi, серверы, бухгалтерия, госконтур и т.д. «Нужны ли виланы?» — да: без них бухгалтерия и гостевой Wi-Fi в одной каше с серверами, а это провал по 152-ФЗ.
- **Trunk vs access** — access: порт одного VLAN (к ПК). Trunk: порт несёт много VLAN с тегами (между свитчами).
- **L2 vs L3 свитч** — L2 переключает внутри сети, L3 ещё и маршрутизирует между VLAN. Ядро у нас L3.
- **Collapsed core** — ядро и агрегация в одном слое. Для 500 чел отдельная агрегация не нужна.
- **MLAG / стек / iStack** — два физических свитча работают как один логический: линк в каждый = нет единой точки отказа.
- **LACP** — склейка двух линков в один логический (2×10G).
- **PoE / PoE+ / PoE++** — питание по витой паре: телефоны (af, 15 Вт), точки Wi-Fi (at, 30 Вт), мощные ТД (bt, 60–90 Вт).
- **802.1X** — аутентификация устройства на порту свитча (чужой ноут в розетку — не работает).
- **VRF** — виртуальные маршрутизаторы внутри одного ядра: госконтур изолирован на уровне маршрутизации.
- **QoS / EF** — приоритизация трафика; голос телефонии идёт первым (EF = expedited forwarding).
- **NGFW** — файрвол нового поколения: видит приложения, не только порты; IPS, URL-фильтрация.
- **2 ISP с разной физикой** — два провайдера через разные трассы в здание; один ввод = фиктивное резервирование.

## Железо и ЦОД

- **1U/2U** — высота сервера в стойке (4,45 см). 42U — высота стойки.
- **OOB / IPMI / iLO / iDRAC** — удалённое управление сервером вне ОС: включить, посмотреть консоль, переустановить — не ехать в серверную. Критично при одном админе.
- **Hot-swap** — замена диска/БП без выключения.
- **ИБП online (double conversion)** — питание всегда идёт через инвертор: идеальное качество + 0 мс переключение. Line-interactive — дешёвые офисные, для серверной нельзя.
- **АВР** — автоматический ввод резерва: запуск генератора при пропаже сети за 10–30 сек.
- **ДГУ** — дизель-генератор. ИБП держит 15–30 мин, ДГУ — хоть сутки (пока есть солярка).
- **N+1** — на один компонент больше, чем нужно: два кондиционера там, где хватит одного.
- **A/B питание** — два независимых ввода в каждую стойку, серверы с двумя БП.
- **АУПТ газовое** — пожаротушение газом, не убивающим железо. Обязательно >24 м² (СП 5.13130).

## Телефония

- **SIP-транк** — канал телефонии от оператора по IP. У нас два оператора с автопереключением.
- **ВАТС** — облачная АТС у оператора (аренда). У нас своя MikoPBX + ВАТС как резерв.
- **AMI/ARI** — API Asterisk: интеграция телефонии с CRM (карточка клиента при звонке, click-to-call).

## Комплаенс

- **152-ФЗ** — закон о персданных. Бухгалтерия/кадры = ИСПДн, уровень УЗ-3/4.
- **УЗ-1…4** — уровни защищённости ПДн, от них зависит набор мер (приказ ФСТЭК №21).
- **Оборотный штраф** — с 30.05.2025: повторная утечка ПДн = 1–3% выручки, мин. 25 млн.
- **СЗИ от НСД** — защита от несанкционированного доступа (Dallas Lock), нужен класс 6 для УЗ-3/4.
- **WORM** — write once read many: записал — стереть нельзя. Для архива и следователей.
- **Object Lock** — то же в S3-облаках: immutability.
- **GOV-контур** — изолированный сегмент под госзаказчиков: VPN+MFA, jump-host, логирование.

## Ответы-признаки «своего» (короткие формулы)

- «Почему не X?» → «Потому что TCO/риски: …, план Б задокументирован.»
- «А если сломается?» → «Отказ компонента покрыт N+1 / кластером / ЗИП; регламент замены — в репе.»
- «А по закону?» → «152-ФЗ закрыт пакетом в `08`, архив на ленте с WORM.»
- Не знаешь точной цифры → «Оценка из КП, порядок такой-то; точная — после запроса поставщиков, это заложено в этап 0.»
