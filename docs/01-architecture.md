## Контуры (сегментация)

| Контур | Содержимое | Доступ |
|---|---|---|
| MGMT | OOB/iLO/iDRAC, управление свитчами | только jump-host |
| USERS | Рабочие места общего контура | стандарт |
| VOICE | Телефония | QoS |
| WIFI-CORP / WIFI-GUEST | Беспровод | 802.1X / только интернет |
| SERVERS-INFRA | Инфра-ВМ (каталог, мониторинг, почта-релеи и т.д.) | по ACL |
| SERVERS-DEV | Разработка, хостинг сервисов | ограниченно из USERS |
| BUH-HR | 1С, ЗУП, АРМ бухгалтерии/HR | ИСПДн, см. `08` |
| GOV | Проекты госзаказчиков (задел) | VPN+MFA, jump-host, журналирование |
| CALLCENTER | Операторы 24/7 | QoS, приоритет |

## Ключевые архитектурные решения (ADR-кратко)

1. **Collapsed core** — для 500 чел уровень агрегации не нужен.
2. **HCI/Ceph вместо SAN** — масштаб 50–100 ВМ не окупает отдельную СХД.
3. **Proxmox вместо VMware** — Broadcom сделал VMware в РФ недоступным и неподъёмным; план Б — zVirt (реестр).
4. **Российский NGFW** — единственный способ иметь легальные обновления сигнатур в РФ 2026.
5. **Linux-first на рабочих местах (80/20)** — лицензионная чистота + экономия.
6. **Почта в облаке РФ** — почтмейстер из одного админа никакой.
7. **ДГУ обязателен** — промзона + КЦ 24/7.
8. **Задел под госконтур сейчас** (VLAN, шкаф, трассы) — дёшево сегодня, дорого завтра.

## Что предлагается сверх ТЗ (от себя)

Бизнес просил «предложить что-то от себя»:

1. **MDM/инвентаризация с первого дня (GLPI+Snipe-IT)** — иначе через год никто не знает, что где стоит.
2. **Helpdesk-заявки вместо «напиши в личку»** — при одном админе это единственный способ не утонуть и показать руководству объём работ.
3. **Камера и СКУД в серверной** (в ТЗ «камеры не нужны» — предлагаю точечно одну, вопрос на совещание).
4. **Пассивный мониторинг SLA для саппорта** (uptime-дашборд для руководства: Grafana) — «красивые картинки для гендира» бесплатно.
5. **Реестр отечественного ПО для собственной CRM** — НДС 0% на продажи, конкурентное преимущество в тендерах заводов (это деньги, а не комплаенс ради комплаенса).
6. **Ежемесячный тест АВР/ДГУ и квартальный тест восстановления из бэкапа** как регламент — отказоустойчивость, которую не проверяют, не существует.
