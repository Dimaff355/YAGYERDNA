# 18. Мастер-гайд настройки (конец-в-конец)

> Фаза после закупки: оборудование на площадке. Цель: «всё работает, всё звонит, отчёты отправляются».
> Порядок строгий — каждый шаг опирается на предыдущий. Ориентировочный срок: 6–8 недель одного админа + подрядчики на СКС/электрику/АУПТ.

## Фаза 0. День 1–5: приёмка и подготовка

1. Принять оборудование, сверить с заказом, сжечь DOA (проверить всё из коробки в первую неделю — гарантия поставщика тикает).
2. Серверная: питание A/B, холод, АУПТ сданы подрядчиком. Тест: выдернуть вводной автомат — ИБП держит, ДГУ запускается за 30 сек.
3. Собрать jump-точку админа: ноутбук с Ansible/OpenTofu, эта монорепа склонирована, секреты в OpenBao.
4. **Критерий выхода:** в серверной есть питание и холод, у админа есть рабочее место с инструментами.

## Фаза 1. Сеть (неделя 1–2)

По `15-setup-network.md`:
1. Ядро: стек 2× S6730, залить `iac/network/huawei/core-0X.cfg`, проверить iStack и SVI.
2. Периметр: UserGate-кластер по `iac/network/usergate/bootstrap.md`, оба ISP, failover тест выдёргиванием.
3. Этаж 1 — пилот: стек доступа, 2×10G в ядро, тестовый ПК получает IP из USERS-VLAN, интернет есть.
4. Этажи 2–5 по шаблону `access-floorN.cfg` (временно параллельно со старыми 2960-X, потом демонтаж).
5. **Критерий:** с любого этажа ping до ядра и в интернет; failover ISP < 5 сек.

## Фаза 2. Compute (неделя 2–3)

По `iac/docs/RUNBOOK.md` этапы A–B:
1. PVE на 4 ноды (флешка/IPMI), IP из плана.
2. `proxmox-cluster.yml` — кластер, Ceph, OSD. Проверка: `ceph -s` = HEALTH_OK, выключение одной ноды — виртуалки живы (тестовая ВМ).
3. Backup-сервер: PBS, zpool, datastore — `backup.yml`.

## Фаза 3. Инфра-ВМ (неделя 3)

RUNBOOK этапы C–D: шаблон 9000 → `tofu apply` → 8 ВМ за 15 минут. Проверка: ansible ping всем.

## Фаза 4. Сервисы (неделя 3–5)

По `16-setup-compute-services.md`, строго в порядке зависимостей:
1. Keycloak (SSO — от него зависят остальные)
2. Zabbix (мониторинг — он должен видеть всё последующее)
3. GLPI (инвентарь/заявки)
4. Nextcloud (файлы)
5. GitLab + AWX (IaC-движок)
6. MikoPBX ×2 (телефония)
7. PBS-политики + S3-синк (бэкапы всех вышеподнятых!)

**Критерий:** каждый сервис виден в Zabbix и забэкаплен в день запуска, не «потом».

## Фаза 5. Пользователи (неделя 4–8)

По `17-setup-workplaces-telephony.md`:
1. Телефония: транки, очередь КЦ, IVR, CRM-интеграция → тестовый звонок 8-800 → очередь → софтфон.
2. Эталонные образы (Linux ×2, Windows ×1), FOG, пилот 10 мест.
3. Волнами по этажам: 20–40 мест/день. Каждый выданный ПК — в GLPI автоматически (агент в образе).
4. Мониторинг: Telegram-алерты, Grafana-дашборд руководству.
5. **Критерий:** новый сотрудник получает ПК+телефон и работает за 15 минут (почта, файлы, CRM, печать).

## Фаза 6. Закрытие (неделя 8)

1. Пакет ПДн (152-ФЗ): Dallas Lock на BUH-HR, модель угроз, уведомление РКН.
2. LTO-архив: первый дамп бухгалтерии на ленту, картридж в сейф.
3. Регламенты в репе: тест АВР ежемесячно, тест восстановления ежеквартально, замена гарнитур, ЗИП.
4. Отчёт руководству: что построено, во сколько обошлось, как эксплуатируется.
