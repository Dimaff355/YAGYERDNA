## Как применять конфиги

Полный пошаговый порядок — в `docs/15-setup-network.md`. Здесь только механика работы с файлами.

### Принцип

Файлы — **шаблоны под copy-paste в консоль VRP**, а не полные running-config. В них нет паролей: секреты подставляются при заливке (плейсхолдеры вида `<CHANGE_ME_...>`).

### Ядро (iStack из 2)

1. Оба S6730 девственные. На **каждом** отдельно через консоль задаём стековую часть из своего файла (секция `iStack` — она разная: member id, priority, renumber). Перезагружаем, соединяем stack-кабелями (100GE x/0/5–6).
2. После образования стека (`display stack` — 2 member'а, Master/Standby) заливаем **общую часть** (всё после секции iStack) на master одним куском — конфиг в iStack общий.
3. `save` → `y` на оба вопроса.

### Этаж (iStack из 3)

1. Берём `access-floorN.cfg`, делаем замену плейсхолдеров: `floorN` → `floor1`, имя, NTP/SNMP-строки — через `sed` или вручную:
   ```bash
   sed 's/FLOOR/1/g; s/crm-acc-floorN/crm-acc-floor1/' access-floorN.cfg > access-floor1.cfg
   ```
2. На каждом из трёх свитчей — только секция iStack (renumber 1/2/3), reboot, кабели стека кольцом.
3. На master — общая часть, `save`.

### Способы заливки

- **Консоль + paste** — основной способ (9600 8N1, кабель из комплекта). Вставлять порциями по ~50 строк, следить за `Error:`.
- **TFTP**: `tftp 10.10.50.10 get access-floor1.cfg vrpcfg-tmp.cfg` → конфиг применяется построчно из system-view, либо `startup saved-configuration` + reboot (рискованно — только если файл полный).
- **ZTP**: не используем (сеть ещё строится, DHCP+TFTP-инфраструктуры для ZTP на момент развёртывания нет); оставлено как опция на будущие замены по RMA.

### Проверка после заливки

Минимум: `display current-configuration | include <секция>`, `display interface brief`, `display stack`, `display lldp neighbor brief`, `display ospf peer brief`. Полный чек-лист по шагам — `docs/15-setup-network.md`.

### Хранение

- Актуальные running-config снимаем после каждого изменения: `display current-configuration` → файл `backups/<hostname>-YYYYMMDD.cfg` (каталог вне репы, на файловом сервере; в репе — только шаблоны).
- Пароли/communities в репе **не храним**. Плейсхолдеры обязательны.
