# UserGate NGFW — начальная настройка кластера (bootstrap)

> Периметр: кластер active/standby из 2 UserGate NGFW, 2 ISP с failover.
> Автоматизации через API на этом этапе **нет** — вся начальная настройка делается
> руками через веб-консоль (UserGate Management Center / локальная консоль узла).
> Этот файл — чек-лист для админа. Файл в репе, чтобы процедура была воспроизводима.
> Ссылка на сетевой дизайн: `docs/03-network.md`, транзит к ядру: VLAN 998 (10.10.254.0/29), VIP кластера — **10.10.254.2** (default-роут ядра смотрит сюда).

## 0. Подготовка (до стойки)

- [ ] Лицензии UserGate (2 узла, лицензия без ограничения пользователей) — активированы в личном кабинете my.usergate.com.
- [ ] Дистрибутив актуальной версии ПО с сайта (аппаратные модули D-серии приходят с заводским образом — обновить до текущей ветки).
- [ ] Данные провайдеров: ISP-1 (основной) и ISP-2 (резервный) — IP/маска/шлюз, тип подключения (статика/PPPoE). Провайдеры с **разной физикой входа** в здание (docs/03).
- [ ] Ноутбук админа, патч-корды, схема портов:
  - `port1` — WAN-1 (ISP-1), `port2` — WAN-2 (ISP-2), `port3+port4` (LACP) — внутрь, к ядру (Eth-Trunk10 на S6730), `port5` — cluster sync (прямой линк между узлами), `mgmt` — выделенное управление (VLAN 10).

## 1. Первичная настройка каждого узла (по отдельности)

1. Подключиться к консольному порту / дефолтному адресу (см. наклейку; по умолчанию админка на `https://10.5.0.1:8001`, admin/utm — **сразу сменить пароль**).
2. Задать: hostname (`ugate-fw-a` / `ugate-fw-b`), часовой пояс MSK, NTP (10.10.50.10 — после поднятия серверного контура; до этого — ntp1.vniiftri.ru).
3. Обновить ПО до актуальной версии на обоих узлах (**версии должны совпадать до кластеризации**).
4. Управление: разрешить веб-консоль и SSH **только из сети MGMT 10.10.10.0/24** (Сеть → Сетевые интерфейсы → mgmt / Настройки → Администрирование).

## 2. Зоны (Настройки → Зоны)

Создать зоны — по одной на контур (VLAN из ядра приходят транзитом, зоны на NGFW логические, привязаны к интерфейсам/VLAN):

| Зона | Сеть за зоной | Интерфейс |
|---|---|---|
| WAN-1 | ISP-1 | port1 |
| WAN-2 | ISP-2 | port2 |
| LAN-TRANSIT | 10.10.254.0/29 (VLAN 998 к ядру) | bond0 (port3+4, LACP) |
| MGMT | 10.10.10.0/24 | mgmt-интерфейс (или через LAN-TRANSIT) |
| USERS, VOICE, WIFI-CORP, WIFI-GUEST, SERV-INFRA, SERV-DEV, BUH-HR, GOV, CALLCENTER | соотв. 10.10.X.0/24 | достижимы через LAN-TRANSIT (L3 на ядре) |

> Тонкость: NGFW — L3-хоп за ядром. Межзонный трафик внутренних VLAN идёт **через ядро**; чтобы NGFW видел и фильтровал его, внутренние сети объявляются зонами с интерфейсом LAN-TRANSIT, а на ядре — policy-based routing / full-mesh через транзит. **Минимально рабочий вариант на старте:** фильтруем только north-south (всё внутрь/наружу периметра), а межсегментную фильтрацию внутренних VLAN включаем фазой 2 (hairpin через NGFW или перенос SVI изолированных контуров BUH-HR/GOV на NGFW). Это осознанное упрощение — зафиксировано здесь, чтобы не «забыть».

## 3. Кластер active/standby (Настройки → Кластер)

1. На `ugate-fw-a`: включить кластер, роль — первый узел; интерфейс синхронизации — `port5` (прямой линк).
2. Задать кластерные (виртуальные) адреса:
   - **LAN-TRANSIT: 10.10.254.2/29** ← default-шлюз для ядра (уже прописан в `core-01.cfg`);
   - WAN-1 VIP, WAN-2 VIP — если провайдеры выдали подсети; если каждый ISP даёт один IP на устройство — VIP не нужен, failover через health-check (п.4).
3. На `ugate-fw-b`: присоединить к кластеру (авторизация по паролю кластера). Проверить: статус «Узел 1 — Active, Узел 2 — Standby», синхронизация конфигурации и сессий — OK.
4. Проверка failover: выдернуть WAN на active → standby поднимает VIP, сессии TCP переустанавливаются (для HA-сессий нужна включённая синхронизация состояний — включить).

## 4. Два ISP и failover (Сеть → Интерфейсы / Балансировка)

1. `port1`: настройки ISP-1 (статика/PPPoE). `port2`: ISP-2.
2. **Проверка канала (health-check):** включить для обоих WAN-интерфейсов — ICMP-опрос опорных хостов за провайдером (напр. шлюз ISP + 8.8.8.8/77.88.8.8), интервал 5 с, 3 промаха = канал down.
3. Режим: **основной/резервный** (ISP-1 приоритет). Балансировку трафика не включаем — осложняет траблшутинг и SIP.
4. Тест: отключить порт ISP-1 → интернет у пользователей жив через ISP-2 (проверить с хоста из USERS: `traceroute`, смена внешнего IP).

## 5. NAT (Политики сети → NAT и маршрутизация)

- NAT (masquerade) на WAN-1 и WAN-2 для зон: USERS, WIFI-CORP, WIFI-GUEST, VOICE (нужен выход SIP-операторам), CALLCENTER, BUH-HR, SERV-INFRA (обновления), SERV-DEV.
- **GOV — отдельное правило NAT** (учётный трафик госконтура, если контур подтверждён — docs/08).
- MGMT — без NAT в интернет (железо в интернет не ходит; обновления Huawei — скачиваются админом вручную).
- Port-forwarding входящий: на старте — **ничего не публикуем**. Публикации (почта VK WorkSpace — облачная, CRM внешних веб-сервисов) — отдельной задачей с WAF (PT AF опционально, docs/03).

## 6. Базовые правила МЭ (Политики сети → Межсетевой экран)

Принцип: сверху разрешающие, внизу **«Запретить всё» + лог**. Инспекция приложений включена на разрешающих правилах в интернет.

| # | Источник | Назначение | Сервисы | Действие | Комментарий |
|---|---|---|---|---|---|
| 10 | MGMT | Все внутренние зоны | SSH, SNMP, ICMP, HTTPS | Разрешить | только с IP админа/jumphost |
| 20 | USERS, WIFI-CORP | WAN-1, WAN-2 | HTTP/S, DNS, NTP, SMTP/S-IMAP/S (к VK WS) | Разрешить + инспекция | основной выход в интернет |
| 21 | WIFI-GUEST | WAN-1, WAN-2 | HTTP/S, DNS | Разрешить | гостевой — только интернет |
| 22 | WIFI-GUEST | Все внутренние зоны | ANY | **Запретить + лог** | изоляция гостей |
| 30 | USERS → SERV-INFRA | DNS, LDAP/Kerberos (ALD Pro), HTTPS, SMB, RDP | Разрешить | каталог, файлы, порталы |
| 31 | USERS → SERV-DEV | HTTP/S, SSH, Git(9418) | Разрешить | разработка |
| 32 | SERV-INFRA → WAN | HTTP/S, NTP, DNS | Разрешить | обновления ОС/ПО, репозитории |
| 40 | VOICE, CALLCENTER → SERV-INFRA (MikoPBX) | SIP 5060/5061, RTP 10000-20000 | Разрешить | телефония к АТС |
| 41 | SERV-INFRA (MikoPBX) → WAN | SIP, RTP, STUN | Разрешить | 2 SIP-оператора; SIP ALG — **выключить** (ломает SIP) |
| 50 | BUH-HR → SERV-INFRA | 1С (1540-1541, 1545), SMB | Разрешить | 1С-клиенты |
| 51 | BUH-HR → WAN | HTTPS | Разрешить + инспекция | банк-клиенты, ЭДО, ФНС |
| 60 | GOV → WAN | HTTPS (whitelist по URL-категориям/списку) | Разрешить | только согласованные ресурсы |
| 61 | GOV ↔ все внутренние зоны | ANY | **Запретить + лог** | изоляция госконтура |
| 70 | SERV-INFRA (Zabbix 10.10.30.11) → все зоны | SNMP, ICMP, Zabbix-agent 10050 | Разрешить | мониторинг |
| 80 | VPN-USERS → USERS/SERV-INFRA/SERV-DEV | RDP, SSH, HTTPS, SMB | Разрешить + MFA на подключении | удалёнка |
| 99 | ANY → ANY | ANY | **Запретить + лог** | default deny |

> DHCP: **серверы DHCP — внутренние** (10.10.50.10/11), relay — на SVI ядра (`dhcp select relay` в `core-01.cfg`). На UserGate DHCP для пользовательских VLAN **не поднимаем**. Опционально — маленький DHCP на UserGate только для служебного сегмента WAN/устройств вне офиса. UserGate может работать и DHCP-relay — не используем, relay уже на ядре.

## 7. VPN-сервер для удалёнки

Что поддерживает UserGate (ветка 7.x):
- **L2TP/IPsec** — основной сценарий remote-access VPN «из коробки», клиенты встроены в Windows/РЕД ОС/macOS/мобильные.
- **Site-to-site IPsec (IKEv1/IKEv2)** — для связки с площадками заказчиков, если понадобится.
- **WireGuard — не поддерживается нативно** (на момент настройки; проверить changelog актуальной версии). Если бизнесу критичен WireGuard (скорость, мобильные) — поднимаем отдельно на ВМ в DMZ (SERV-INFRA) с пробросом UDP-порта через NGFW; в базовый контур не входит.

Настройка L2TP/IPsec:
1. Настройки → VPN → включить серверный профиль L2TP/IPsec: PSK (длинный, в сейф) + пользовательская аутентификация через **LDAP (ALD Pro)** — не заводить локальных пользователей.
2. Пул адресов VPN-USERS: 10.10.100.0/24 (вне VLAN-плана, маршрут на ядре: `ip route-static 10.10.100.0 24 10.10.254.2`).
3. MFA — через ALD Pro/Keycloak, если доступно в версии; иначе компенсирующая мера: доступ VPN только с выделенных устройств + журналирование.
4. Правило МЭ №80 (таблица выше) — только нужные сервисы, не ANY.
5. Запретить split-tunnel для GOV/BUH-HR-пользователей, если они будут в VPN (трафик ПДн — только через корпоративный шлюз).

## 9. Приёмка периметра (чек-лист)

- [ ] С хоста в USERS: интернет работает, внешний IP = ISP-1.
- [ ] Отключение ISP-1: < 10 с перерыва, внешний IP = ISP-2; возврат — обратно на ISP-1.
- [ ] Выключение active-узла: standby подхватывает VIP 10.10.254.2, интернет жив.
- [ ] Гостевой Wi-Fi: интернет есть, `ping 10.10.20.1` / доступ к внутренним — **нет** (правило 22).
- [ ] Из USERS нет доступа в GOV и в админские интерфейсы железа.
- [ ] VPN-клиент подключается, получает 10.10.100.x, доступен RDP до разрешённого хоста, остальное закрыто.
- [ ] В журнале видны отброшенные пакеты по правилу 99.
